### 1.2 核心问题诊断

#### 问题一：homeservice-payment 与 homeservice-order 高度重合

**PaymentController**（8 个接口）：

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | /page | 分页查询支付记录 |
| GET | /{id} | 根据ID查询 |
| GET | /no/{paymentNo} | 根据流水号查询 |
| GET | /order/{orderId} | 根据订单ID查询 |
| POST | / | 创建支付记录 |
| POST | /process | 处理支付（变更状态 + 发MQ） |
| PUT | /{id}/refund | 退款 |
| PUT | /{id} | 更新支付记录 |
| DELETE | /batch | 批量删除 |

**PaymentServiceImpl 核心逻辑：**

`java
// 1. processPayment - 唯一的业务逻辑
@GlobalTransactional(timeoutMills = 300000, name = "payment-process")
@Transactional
public boolean processPayment(Payment payment) {
    payment.setStatus(2);           // 改为已支付
    payment.setPayTime(now());
    boolean saved = save(payment);  // 入库
    if (saved) {
        sendOrderPaidEventWithLocalTable(payment); // 发MQ通知order
    }
    return saved;
}

// 2. refundPayment - 退款
public boolean refundPayment(Long paymentId, String reason) {
    payment.setStatus(4);           // 改为已退款
    payment.setRefundAmount(...);
    payment.setRefundTime(now());
    return updateById(payment);
}
`

**Order 状态机已覆盖支付生命周期：**

`
PENDING(1, "待支付")
  → PAID(2, "待服务")       ← processPayment() 触发
  → DISPATCHED(3, "已派单")
  → ACCEPTED(4, "已接单")
  → IN_PROGRESS(5, "服务中")
  → COMPLETED(6, "待评价")
  → CONFIRMED(7, "已完成")
CANCELLED(8, "已取消")
REFUNDED(9, "已退款")        ← refundPayment() 触发
`

**重合度分析：**

| 维度 | homeservice-payment | homeservice-order | 结论 |
|------|---------------------|-------------------|------|
| 支付状态 | 4种状态 | 待支付→待服务隐含已支付 | order 已覆盖 |
| 金额记录 | payment_amount, refund_amount | actual_amount（实付） | 分散在两个表 |
| 退款逻辑 | 仅改状态 | cancelOrder 也涉及退款 | 入口不统一 |
| 微信 SDK | 代码未实现 | 无 | SDK 集成空白 |
| Seata 事务 | @GlobalTransactional | @GlobalTransactional | 跨服务事务增加复杂度 |

**关键发现：** 两个模块依赖几乎完全一致（web + redis + amqp + seata + feign）。支付模块独有的价值仅是 Payment 实体和对应 Mapper。

---

#### 问题二：图片上传/文件管理缺乏独立模块

- FileController 寄宿在 homeservice-service 中，与服务项目管理混在一起
- 没有独立的媒体资源管理能力
- 无 media_file 表记录元数据
- 存储策略硬编码，无法灵活切换 Local/OSS/COS
- 无法支撑小程序界面装修需求（Banner 图、广告位、模块配图等）

---

#### 问题三：homeservice-location 功能单薄

- 仅 3 个内部接口（updateLocation / getNearbyWorkers / getWorkerLocation）
- 无数据库连接（排除 DataSourceAutoConfiguration），纯 Redis 微服务
- getNearbyWorkers 使用 KEYS * 遍历，存在性能隐患
- 地图 SDK 能力（逆地理编码、城市列表）尚未集成
- 为 3 个内部接口部署独立微服务，运维成本远大于业务价值

---

#### 问题四：统计查询在三模块中重复

| 功能 | OrderController | StatisticsController | FinanceController | 建议 |
|------|:---:|:---:|:---:|------|
| 热门服务 | GET /top-services | GET /top-services | — | 保留 order，删除 statistics |
| 订单状态分布 | GET /status-distribution | GET /order-status | — | 保留 order |
| 订单趋势 | GET /trend | GET /order-trend | — | 保留 statistics |
| 营收趋势 | GET /revenue-trend | GET /revenue-trend | GET /income | 归入 finance |
| Dashboard 总览 | — | GET /dashboard | GET /overview | 合并到 statistics |

```java
@Tag(name = "定位服务")
@RestController
@RequestMapping("/location")
@RequiredArgsConstructor
public class LocationController {

    private final LocationService locationService;

    // ========== 服务人员位置（内部接口） ==========
    @PutMapping("/worker/update")
    public Result<Void> updateWorkerLocation(@RequestBody WorkerLocationDTO dto) {
        locationService.updateWorkerLocation(dto.getWorkerId(),
                dto.getLatitude(), dto.getLongitude());
        return Result.success();
    }

    @GetMapping("/worker/nearby")
    public Result<List<WorkerLocationVO>> getNearbyWorkers(
            @RequestParam Double latitude,
            @RequestParam Double longitude,
            @RequestParam(defaultValue = "5000") Integer radius) {
        return Result.success(locationService.getNearbyWorkers(latitude, longitude, radius));
    }

    @GetMapping("/worker/{workerId}")
    public Result<WorkerLocationVO> getWorkerLocation(@PathVariable Long workerId) {
        WorkerLocationVO location = locationService.getWorkerLocation(workerId);
        return location != null ? Result.success(location) : Result.error("位置信息不存在");
    }

    // ========== C端公开接口 ==========
    @GetMapping("/geocode/reverse")
    public Result<AddressVO> reverseGeocode(
            @RequestParam Double latitude, @RequestParam Double longitude) {
        return Result.success(locationService.reverseGeocode(latitude, longitude));
    }

    @GetMapping("/current-city")
    public Result<CityVO> getCurrentCity(
            @RequestParam Double latitude, @RequestParam Double longitude) {
        return Result.success(locationService.getCurrentCity(latitude, longitude));
    }

    @GetMapping("/city/hot")
    public Result<List<CityVO>> getHotCities() {
        return Result.success(locationService.getHotCities());
    }

    @GetMapping("/city/list")
    public Result<Map<String, List<CityVO>>> getAllCities() {
        return Result.success(locationService.getAllCities());
    }
```

```java
        WorkerLocationVO loc = WorkerLocationVO.builder()
                .workerId(workerId).latitude(latitude).longitude(longitude)
```

```java
// 存储策略接口
public interface StorageStrategy {
    String upload(MultipartFile file, String fileKey);
    boolean delete(String fileKey);
    String getUrl(String fileKey);
    String getType();
}

// 存储策略工厂
@Component
public class StorageStrategyFactory {
    private final Map<String, StorageStrategy> strategyMap;

    public StorageStrategyFactory(List<StorageStrategy> strategies) {
        this.strategyMap = strategies.stream()
                .collect(Collectors.toMap(StorageStrategy::getType, s -> s));
    }

    public StorageStrategy getStrategy(String type) {
        StorageStrategy strategy = strategyMap.get(type);
        if (strategy == null) throw new BusinessException("不支持的存储类型: " + type);
        return strategy;
    }
}

// 配置驱动选择存储后端
@Component
public class StorageConfig {
    private final SysConfigFeignClient sysConfigClient;

    public String getCurrentStorageType() {
        return sysConfigClient.getConfigValue("storage.type", "local");
    }
}
```
